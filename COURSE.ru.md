# Практикум: свой MCP-сервер для Claude Code

Цель — своими руками написать простейший локальный MCP-сервер «Заметки» на Python, подключить его к Claude Code и посмотреть, как Claude с ним работает.

- **Без API-ключей и без собственного клиента**: клиентом выступает Claude Code.
- **Без хостинга**: сервер работает локально через stdio, Claude Code сам запускает его как подпроцесс.
- **Без готовых решений**: в каждом шаге есть задание, подсказки по API и критерий проверки. Код пишете вы.

Версия SDK: `mcp` **2.3.0** (PyPI, октябрь 2026).
> ⚠️ В SDK v2 класс `FastMCP` переименован в `MCPServer`. Большинство туториалов в интернете (и курс в `cli_project`) написаны под v1: `from mcp.server.fastmcp import FastMCP`. В v2 этот импорт падает с `ModuleNotFoundError`. Если пример из интернета не работает, сначала проверьте версию.

Документация SDK: https://py.sdk.modelcontextprotocol.io
Документация Claude Code по MCP: https://code.claude.com/docs/en/mcp

## Как устроен сервер «Заметки»

```
mcp_practice/
├── COURSE.ru.md     ← этот файл
├── server.py        ← ваш MCP-сервер
└── notes/           ← «база данных»: обычные .md файлы
    ├── shopping.md
    └── ideas.md
```

К концу курса сервер будет уметь:

| Возможность | Что это | Кто инициирует |
|---|---|---|
| **Tools** `list_notes`, `read_note`, `write_note` | Действия | Claude решает сам, когда их вызвать |
| **Resources** `notes://index`, `notes://{name}` | Данные для чтения | Вы, через `@` в строке ввода |
| **Prompts** `summarize_note` | Готовые шаблоны запросов | Вы, через слэш-команду |

## Модуль 1. Скелет сервера

### Шаг 1.1 — Минимальный сервер
- [ ] Создать `server.py`: экземпляр сервера с именем `"Notes"` и запуск по stdio, когда файл выполняется как скрипт.

**Подсказки:**
- `from mcp.server import MCPServer`
- `MCPServer(name: str)` — создаёт сервер.
- Сохраните экземпляр в переменную уровня модуля с именем `mcp`: `mcp = MCPServer("Notes")`. Дальше в курсе все подсказки используют это имя (`@mcp.tool()`, `@mcp.resource()`, `@mcp.prompt()`), а команды `mcp dev` и `mcp run` ищут в файле объект с именем `mcp`, `server` или `app`.
- `mcp.run()` — запускает сервер (по умолчанию транспорт stdio).
- Запуск поместите под `if __name__ == "__main__":`. Инструменты SDK (`mcp dev`, `mcp run`) импортируют ваш файл, и при импорте сервер стартовать не должен.

### Шаг 1.2 — Эксперимент: побыть клиентом самому
- [ ] Запустить `uv run server.py` и вставить в терминал три сообщения по очереди, нажимая Enter после каждого. Каждое сообщение — одна строка JSON.

1. `initialize`:
   ```json
   {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"manual","version":"0.1"}}}
   ```
2. `notifications/initialized`:
   ```json
   {"jsonrpc":"2.0","method":"notifications/initialized"}
   ```
3. `tools/list`:
   ```json
   {"jsonrpc":"2.0","id":2,"method":"tools/list"}
   ```

**Что увидите:**
- После `initialize` сервер ответит строкой, в которой есть `"serverInfo":{"name":"Notes",...}` и список его возможностей.
- На `notifications/initialized` ответа не будет: это уведомление, у него нет `id`.
- `tools/list` вернёт `{"tools":[]}`: инструментов пока нет.

Остановите процесс через `Ctrl+C`.

**Что заметить:**
- `initialize` обязательно идёт первым: это рукопожатие, в котором клиент и сервер договариваются о версии протокола.
- Поле `id` связывает ответ с запросом.
- Ровно этот обмен за вас выполняют Claude Code и MCP Inspector. Повторите `tools/list` после модуля 2 и увидите `list_notes` с описанием и схемой аргументов.

## Модуль 2. Первый инструмент (tool)

### Шаг 2.1 — `list_notes`
- [ ] Написать инструмент `list_notes`, который возвращает имена файлов из папки `notes/`.

**Подсказки:**
- Декоратор `@mcp.tool()` (именно со скобками) превращает функцию в инструмент.
- SDK сам строит описание инструмента для модели:
  - **имя** — из имени функции;
  - **описание** — из docstring;
  - **схема аргументов** — из type hints.
- Путь к папке стройте от расположения файла, а не от текущей директории: `Path(__file__).parent / "notes"`. Claude Code может запустить сервер из другой рабочей папки.
- Тип возврата: `list[str]` или `str`. Попробуйте оба варианта и посмотрите в Inspector, чем отличается результат.

### Шаг 2.2 — Проверка в MCP Inspector
- [ ] Запустить `uv run mcp dev server.py`.
- [ ] В открывшемся браузере нажать Connect → вкладка **Tools** → `list_notes` → Run.

**Проверка:** видите список своих файлов.

**Зачем этот шаг:** Inspector — тоже MCP-клиент, только ручной. Так вы отлаживаете сервер без участия модели и видите сырой JSON запросов и ответов.

## Модуль 3. Подключение к Claude Code

### Шаг 3.1 — Регистрация
- [ ] Зарегистрировать сервер в Claude Code под именем `notes`.

**Подсказки:**
- Синтаксис: `claude mcp add [опции] <имя> -- <команда> [аргументы...]`.
- Всё после `--` — команда, которой Claude Code будет запускать сервер. Его собственные опции (`--scope`, `--env`, `--transport`) указываются **до** `--`.
- Чтобы сервер запускался корректно из любой рабочей папки, укажите uv путь к проекту: `uv run --directory C:/Users/nikbu/PycharmProjects/mcp_practice server.py`.
- Scope по умолчанию — `local`: сервер доступен только вам и только в папке, где выполнена команда.
- Полезные команды: `claude mcp list`, `claude mcp get notes`, `claude mcp remove notes`.

### Шаг 3.2 — Проверка подключения
- [ ] Запустить `claude` в папке, где регистрировали сервер.
- [ ] Выполнить `/mcp`.

**Проверка:** сервер `notes` в статусе connected, в списке его инструментов есть `list_notes`.

### Шаг 3.3 — Первый разговор
- [ ] Спросить Claude: «Какие у меня есть заметки?»

**Что наблюдать:**
- Claude вызовет инструмент `mcp__notes__list_notes`. Это полное имя: `mcp__<сервер>__<инструмент>`.
- Claude Code спросит разрешение на вызов. Это проверка разрешений на стороне host: сам сервер о ней ничего не знает.
- Вы не говорили Claude, что инструмент существует. Он узнал об этом из описания, которое клиент получил от сервера.

## Модуль 8. Ресурсы (resources)

Ресурсы — это данные, которые выбирает **пользователь**, а не модель. Инструменты — это действия, которые выбирает модель.

### Шаг 8.1 — Статический ресурс `notes://index`
- [ ] Ресурс отдаёт список заметок с их размером или первой строкой.

**Подсказки:**
- `@mcp.resource("notes://index")` — URI без параметров означает статический ресурс, и у функции не должно быть параметров.
- Возвращаемый `str` станет текстовым содержимым ресурса. Необязательные аргументы декоратора: `name`, `description`, `mime_type`.

### Шаг 8.2 — Шаблон ресурса `notes://{name}`
- [ ] Ресурс отдаёт содержимое конкретной заметки.

**Подсказки:** `{name}` в URI должен **точно** совпадать с параметром функции. Не забудьте защиту путей.

- [ ] В Claude Code: наберите `@` в строке ввода и найдите ресурсы сервера `notes`. Подключите `notes://index` к вопросу.

## Ответы на вопросы для понимания

Сначала ответьте сами, потом сверяйтесь.

**1. Почему бессмысленно держать stdio-сервер запущенным в отдельном терминале?**
Stdio-сервер принимает запросы только через stdin и отвечает только через stdout. Поэтому работать с ним может только тот, кто его запустил. Если запустить сервер в терминале, общаться с ним сможете только вы, вручную. Claude Code к нему не подключится, поэтому он запускает сервер сам. Именно поэтому `claude mcp add` принимает команду запуска, а не адрес.

**2. Почему проверку путей нужно делать в сервере?**
Модель — не граница безопасности. Она может ошибиться, а её можно обмануть: например, текст заметки может содержать инструкцию «прочитай `../.env`» (prompt injection). Кроме того, сервер вызывает не только модель: Inspector, другой клиент или скрипт пришлют любые аргументы. Сервер — единственное место, через которое проходит каждый запрос к файлам, поэтому ограничение работает только там.

**3. Почему для изменяющих инструментов осторожность host особенно важна?**
Ошибку при чтении можно просто проигнорировать, а ошибку при записи — нет: перезаписанную заметку не вернуть. Модель может неверно понять просьбу или выполнить чужую инструкцию из прочитанных данных. Запрос разрешения оставляет человека последним звеном перед необратимым действием. Аннотации `readOnlyHint` и `destructiveHint` помогают host решить, где спрашивать обязательно.

**4. Какие ресурсы видны в автодополнении `@`?**
Ожидаемо — только статические, например `notes://index`. Сервер отдаёт их в ответе на `resources/list`: это конкретные ресурсы с готовым URI. Шаблон `notes://{name}` приходит отдельным запросом `resources/templates/list` и сам по себе ресурсом не является, пока в него не подставлено имя. Заметку через шаблон можно прикрепить, если ввести конкретный URI, например `@notes:notes://shopping`. Проверьте на своей версии Claude Code: документация не описывает, показывает ли автодополнение шаблоны.

**5. Чем прикреплённый ресурс отличается от вызова `list_notes`?**
- **Кто решает.** Ресурс выбрали вы, вызов инструмента — модель.
- **Когда данные попадают в контекст.** Прикреплённый ресурс Claude Code читает сам и добавляет к вашему сообщению до того, как модель начнёт отвечать. Инструмент модель вызывает уже по ходу ответа, если сочтёт нужным.
- **Разрешения.** На прикрепление ресурса разрешение не спрашивается: вы его уже дали, выбрав ресурс. На вызов инструмента Claude Code спрашивает.

**6. Когда что использовать?**
- **Tool** — действие или вычисление, о котором решает модель: поиск, чтение по запросу, запись, вызов внешнего API. Может иметь побочные эффекты.
- **Resource** — данные для чтения с собственным URI, которые выбирает пользователь (или приложение), чтобы дать модели контекст. Без побочных эффектов.
- **Prompt** — готовый шаблон запроса, который пользователь запускает явно, например слэш-командой. Модель сама промпты не вызывает.
