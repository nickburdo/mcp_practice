# Model Context Protocol: краткий обзор

Model Context Protocol (MCP) — открытый протокол, который стандартизирует
то, как приложения с языковыми моделями получают доступ к внешним данным
и инструментам. Вместо отдельной интеграции под каждый сервис достаточно
один раз реализовать MCP-сервер, и им сможет пользоваться любой
совместимый клиент.

## Основные участники

- **Хост** — приложение, в котором работает модель (IDE, чат-клиент,
  агент в терминале).
- **Клиент** — компонент внутри хоста, который держит соединение
  с одним сервером.
- **Сервер** — программа, которая предоставляет возможности: данные,
  действия и шаблоны запросов.

## Что может предоставлять сервер

1. **Ресурсы** — данные только для чтения: файлы, записи из базы,
   ответы API. Каждый ресурс адресуется по URI.
2. **Инструменты** — функции, которые модель может вызвать: выполнить
   поиск, создать запись, отправить запрос.
3. **Промпты** — заготовленные шаблоны сообщений, которые пользователь
   может выбрать в интерфейсе хоста.

## Транспорты

Чаще всего используются два способа связи:

- **stdio** — клиент запускает сервер как дочерний процесс и общается
  с ним через стандартные потоки ввода-вывода. Удобно для локальных
  инструментов.
- **Streamable HTTP** — сервер работает как отдельный веб-сервис,
  к которому могут подключаться удалённые клиенты.

## Почему это удобно

Протокол разделяет ответственность: авторы серверов думают только о своих
данных и действиях, а авторы клиентов — только о взаимодействии с
моделью. Один сервер с заметками, как этот каталог, может одинаково
работать и в редакторе кода, и в чат-приложении.
